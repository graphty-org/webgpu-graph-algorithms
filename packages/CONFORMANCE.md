# @graphty/graph-format: API conformance audit

Lens: API conformance to `design/graph-format/graph-format-design.md` (the graphty-monorepo copy,
read 2026-09-13). Package audited: `packages/graph-format` at 0.1.0, after `pnpm run build:all`.

STATUS AFTER AUDIT ROUND 1 (2026-09-13, fixer pass): findings F1-F5 and notes N1-N4, N6-N9 are
resolved in the code (`packages/STATUS.md`, section "Audit round 1", lists every change); N5 and
N10 stand as documented. `test/audit/conformance-semantics.test.ts` now passes in full (71 / 71);
the tables below keep the audit's original wording with a "Resolved:" note where the status changed.

How the tables were produced:

- Section 12.2 was checked MECHANICALLY: `tmp/conformance-check.ts` (run with
  `pnpm exec tsx ../../tmp/conformance-check.ts` from `packages/graph-format`) extracts the fenced
  listing of section 12.2 into `tmp/design-12-2.d.ts`, loads it and `dist/graph-format.d.ts` into
  one TypeScript 5.9.3 program and compares every export: presence, declaration kind, every member
  (name, optionality, readonly, accessor form), every call / construct signature (parameter names,
  optionality, rest, types, return type) and every alias body. Types are compared by mutual
  assignability through the checker, falling back to normalised text for generic aliases and
  generic interface members. Result: 126 names in the design, 126 in dist, 0 missing, 0 extra, 122
  identical, 4 classes with notes (below). The 12.3 assignability promises hold: `GraphBuilder` to
  `GraphSink`, `GraphSnapshot` and `ReverseView` to `AdjacencyView`.
- `test/audit/conformance-exports.test.ts` pins the export list of `src/index.ts` (names and
  kinds, through the checker, plus the runtime value exports) to the section 12.2 listing so the
  check runs in CI without the design document.
- Sections 3.9, 6.6, 7.2, 7.3, 8.1, 9 and 11 were walked by hand with probe scripts
  (`tmp/probe-*.ts`) and the results turned into `test/audit/conformance-semantics.test.ts`
  (71 tests: 66 passed and 5 deliberately failed at audit time; all 71 pass after round 1).
- Every deviation recorded in `packages/STATUS.md` is classified below as (a) consistent with the
  design's decision log, (b) a justified silence-fill, or (c) a contradiction of the design.

Status vocabulary: `implemented` = matches the design; `deviates` = present but differs
observably; `missing` = absent.

## 1. Findings (defects)

| Id  | Severity | Design                                                                     | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Pinned by                                                                                                                                                                                               |

| F1  | major    | 11.1, 6.5, 12.2                                                            | `freeze({ duplicateEdges })` does not validate the override: a value outside `DuplicatePolicy` (e.g. `"bogus"`, a typo from a JS caller or a config value) falls through `walkDuplicates()` as a MERGE policy with survivor `group[0]` (i.e. behaves as `"first"`), and because a merge policy permanently rewrites the builder (6.5) the parallels are destroyed with no error. The constructor validates the same option (`E_UNSUPPORTED`); the per-freeze override is the only path that does not. Repro: 3 edges a->b(1), a->b(5), a->c(3); `freeze({ duplicateEdges: "bogus" })` returns 2 edges and `builder.edgeCount === 2`. | `conformance-semantics.test.ts` F1 (fails) Resolved: `freeze()` checks every FreezeOptions field (`E_UNSUPPORTED`; the DuplicatePolicy set is shared with the constructor in `src/builder/options.ts`). |
| F2  | minor    | 11.1 ("the failing operation is not partially applied"), package CLAUDE.md | `addEdgeRecord` / `addNodeRecord` are not atomic: the element is added and `mutationCount` bumped before the attributes are written, so a bad attribute (lone surrogate, bigint, wrong declared dtype) throws AFTER the edge / node exists with the earlier keys written. An importer that catches per-record errors and re-pushes the sanitised record creates a duplicate edge. STATUS records this as a deviation; it contradicts 11.1 verbatim.                                                                                                                                                                                  | F2 (fails) Resolved: every attribute value (and the weight) is validated before the element is added; `setDirected` expansion checks both declarations first.                                           |
| F3  | minor    | 3.6, 7.2, 16.1 P8                                                          | `isSymmetric()` compares forward and reverse rows position by position, so a directed multigraph whose parallels carry the same weights in a different order reports `false` although the arc multiset is closed under reversal with equal weights (the design's definition; P8's oracle is "a set comparison"). False negatives only cost a consumer a `toUndirected()` copy, hence minor.                                                                                                                                                                                                                                          | F3 (fails) Resolved: `computeSymmetric` compares each run of parallel arcs as a sorted weight multiset.                                                                                                 |
| F4  | minor    | 5.8, 12.2, 7.5                                                             | The lazy state lives in a TypeScript `private readonly state` field, which is a public, enumerable own property at runtime: `Object.keys(snapshot)` lists `state` next to the 19 public fields, `{ ...snapshot }` and `JSON.stringify` reach the view cache, and `structuredClone` walks `state` (typed arrays, Maps) before it reaches the clone guard. 5.8 says the lazy members "live in ES private fields". STATUS blames the ES2020 target, but tsc downlevels `#fields` to WeakMap helpers for any ES2015+ target, and a one-line `Object.defineProperty(this, "state", { enumerable: false })` would also do.                 | F4 (fails) Resolved: `state` is a non-enumerable own property (`declare` field plus `Object.defineProperty`).                                                                                           |
| F5  | minor    | 5.11, 12.2 (`remapColumn` "rewrites refersTo values")                      | `remapColumn(column, remap, newLength)` rewrites `refersTo` values through the SAME remap whatever the column's domain, so a node column with `refersTo: "edge"` (or an edge column with `refersTo: "node"`) remapped through the node (edge) remap has its references silently rewritten through the wrong index space. Repro: node column `[0, 1, 2]` (edge refs), node remap `[1, INVALID, 0]` gives `[0, 1]` instead of `[2, 0]`. The public helper should either leave cross-space values untouched or throw `E_COLUMN_TYPE`; the internal `remapColumnWith` already takes the second remap.                                    | F5 (fails) Resolved: `remapColumn` rewrites values only when `refersTo === domain`; a short remap is `E_COLUMN_LENGTH` (N8).                                                                            |
